Password strength rules

Registration and profile password updates require all of:

  • At least 8 characters
  • One uppercase letter
  • One lowercase letter
  • One number

Confirm-password is checked only on client side. Passwords hashed by Supabase Auth.

Setting up the project

  1. Install dependencies (npm install). Use npm only; do not add pnpm-lock.yaml (Vercel will pick pnpm and CI will fail).
  2. Copy .env.example to .env.local and set:
    • VITE_SUPABASE_URL
    • VITE_SUPABASE_PUBLISHABLE_KEY
  3. Supabase Dashboard → SQL Editor → New query → paste all of supabase/000_init.sql → Run.
  4. Seed the admin account:
    1. Supabase Dashboard → Authentication → Users → Add user.
    2. Email: admin@ust.hk
    3. Set a password.
    4. Enable Auto Confirm User.
    5. Save.
  5. Authentication → Providers → Email → turn off “Confirm email”
  6. Storage → listing-photos → confirm the bucket is set to Public
  7. Database → Publications → set supabase_realtime ON.
  8. That's it! Start the app with npm run dev.

Other miscellaneous things to document

User credentials

Signup internally uses a fake email generated using the username. Usernames become emails in the form of g34mp+{username}@gmail.com (Supabase rejects.local addresses with email_address_invalid). Users still login using username + password.

Generating dummy data after initialising the database

To populate the database with some dummy data, on Supabase run the following and only the following in order:

  1. supabase/003_demo_seed.sql
  2. supabase/005_demo_listing_photos.sql
  3. supabase/006_demo_match_photos_and_listings.sql
  4. supabase/007_fix_broken_and_follow_photos.sql

The credentials for the populated accounts can be found in demo/accounts.csv.

User deletion

Permanent delete is a soft delete. The profile is marked deleted, the user's live/pending listings are taken down, and deals/chats are retained for audit.
